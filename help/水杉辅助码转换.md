# 解书音形 → 水杉辅助码 转换说明

本文说明 `agent_workspace/msime_export.py` 如何把解书音形码表折算成水杉（msime）自定义辅助码方案文件。

- 真源：`dict/dictionary.txt`（单字表，经 `config.DATA_FILE` 读取）
- 产物：水杉「自定义辅助码」目录下的 `<方案名>.txt`，默认 `jieshu.txt`
- 实现：`agent_workspace/msime_export.py`

---

## 一、方案定位

这是一套**粗映射**：只借用解书编码里主码与副码的字母，把它们压成两位辅助码（两位是本方案自定的统一码长，水杉本身也收一位，理由见第三节第 4 条），不重建水杉原生方案的部首字母体系。

由此带来两个直接后果，取用前需知悉：

1. 本方案的码位归属由解书部首表决定，与水杉原生辅助码（如 `妈=nm`、`锕=jk`）**不通用**。
2. 解书的点补（`.F`）信息在两位字母体系里无法表达，一律丢弃。这不影响繁体输入：水杉自带繁体输出（`Ctrl+Shift+F` 简繁切换），用解书码打简体、由上屏结果转繁即可，不必像解书那样靠补码区分。唯一保留的例外是「屮」，理由见 2.4。

### 输出格式（水杉方案文件）

```
# name: 解书音形
# name_en: Elucidative Chinese IME
# 由 agent_workspace/msime_export.py 自解书码表真源生成，请勿手改；规则见 help/水杉辅助码转换.md
不=ar
八=ae
妈=na
……
```

### 导出与部署

```bat
python agent_workspace\msime_export.py                          :: 首次询问目录并写回 config.py
python agent_workspace\msime_export.py --target <目录>           :: 临时指定，不写回
python agent_workspace\msime_export.py --out dictionary_out.txt  :: 沿用旧文件名
```

路径优先级：`--target` > `config.py` 的 `MSIME_DIR` > 交互式询问（首次输入后写回 `config.py`）。本仓库是公开仓库，`MSIME_DIR` 提交时应保持空串；交互式写回只作用于本机工作副本，提交前记得还原（与 `RIME_USER_DIR` 同一约定）。

产物写入纪律与 `migrate_to_rime/rime_export.py` 一致：先写同目录临时文件再替换，旧文件轮转为 `.bak`；内容与旧产物完全相同时跳过写入并打印 `[SKIP]`。

部署步骤：

1. 把产物放进水杉「自定义辅助码」目录（通常 `<水杉安装目录>\helpcodes\custom`，即设置窗口「辅助码」页读取的目录）。
2. 打开设置窗口 →「辅助码」页 → 点「刷新方案」，在双拼/全拼方案下拉框里选中「解书音形」。
3. 之后再改码表重新导出时，若正在使用该方案，需切换一次方案或重启输入法才生效。
4. 文件名即方案 ID（`custom/<去掉 .txt 的文件名>`），改名等于换方案；旧产物 `dictionary_out.txt` 可直接删除。

## 二、转换规则

### 2.1按脚本执行顺序列出:

| 编号  | 规则                                           | 示例                                        |
| --- | -------------------------------------------- | ----------------------------------------- |
| R1  | 舍弃音码，取形码部分 `X`                               | `bu44` → `44`；`ma1n` → `n`；`ba2c;` → `c;` |
| R2  | 点补丢弃：遇到 `.` 即截断，`.` 及其后字符全部不要                | `ck3c.i` → `c`；`b;1u.b` → `u`             |
| R3  | 独体字：`X` 首字符为数字时，查固定表换成两位码，数字后的其余字符忽略         | `bu44` → `4` → `ar`                       |
| R4  | 分号改写：`X` 中的 `;` 换成 `e`（对应未简字副码）              | `ba2c;` → `ce`                            |
| R5  | 单字符补位：折算结果只有 1 位时补 `a`，凑成两位                  | `ma1n` → `n` → `na`                       |
| R6  | 多码取一：同一字有多条编码时按2.3的顺序选一条                     | `解` 有 `k`/`kd` 两型 → 取 `kd`                |
| R7  | 结果校验：最终必须是两位小写字母 `[a-z]{2}`；不满足直接报错终止，不产出半成品 | —                                         |

规则 R3 与 R5 都在「两位」这一约束下产生占位，二者互斥：数字主码走 R3，字母主码缺副码才走 R5。（两位是本方案自定的统一码长；水杉本身也收一位辅助码，为什么仍补位见第三节第 4 条。）

R4 的改写方向另有由来：水杉辅助码只收字母，分号无处安放；而解书体系里分号的上级是 `e`，故把 `;` 统一改写成 `e`。

### 2.2独体字数字主码映射表

独体字无副码，主码数字表示构形类别。十类在两位字母体系里没有可对齐的形码，按固定表占位，统一以 `a` 为前缀。0-9分别为ap, aq, aw, ae, ar, at, ay, au ,ai ,ao。即键盘上数字键下偏右的一排字母键。

### 2.3一字多码的取舍顺序

同一字在真源里可能有多条编码（多音、繁体/异体、不同主码）。先按 R1 得到各自的形码部分并去重（保持真源顺序），再按下列顺序定一条：

1. **唯一候选**：去重后只剩一项，直接取用。
2. **优先不带点补**：候选里存在不含 `.` 的项时，只在其中挑选；含点补的候选全部退出。
3. **取最长**：在剩余候选中选形码部分最长的（即副码最完整的那条）。
4. **优先不含 e**：仍并列时，优先 `e` 不出现在其中的候选。副码优先级为「空副码 > 部首别码 > 余字解析码（余音/余部）> e > ;」，`e` 是跳出余字解析码后的第一兜底，且部首表的 `e` 行留空（`e:<无>`），故副码位上的 `e` 不携带任何可推导的形信息。存在其他候选时取部首别码或余字解析码那条，更经得起推导。当前真源里同长并列共 13 组，无一含 `e`，此条暂未改变任何字的取码，属预防性次序。
5. **首现优先**：依旧并列则取真源里最先出现的一条。
6. **全部带点补**：候选全部含 `.` 时，只有 `屮` 取末位候选（见 2.4），其余字整体舍弃、不写进方案文件。

### 2.4特例与舍弃

**屮：全点补仍取末位**

`屮` 不是繁体字，而是罕见部首字——没有对应的简体，水杉的繁体输出也变不出来。若照「候选全带点补即舍弃」处理，这个字在水杉里就彻底打不出来，故破例保留：其两条编码 `ck3c.i` 与 `ie45.c` 都带点补，取末位，即 `屮=at`。该属个案处理而非通例。

**其他舍弃清单**

当前真源中仅 4 字因「候选全部带点补」被舍弃：**參 隻 見 澤**。四者均为繁体/异体，在两位字母体系下无法给出唯一形码，脚本直接跳过（控制台 `[WARN]` 列出）。舍弃不等于出错：这些字在水杉里只是没有自定义辅助码，其余字不受影响。繁体本身照旧可打——用简体的解书码输入，再经水杉繁体输出转繁（参→參、只→隻、见→見、泽→澤）。这与「屮」不同：屮没有简体可借，故必须保留。

## 三、已知局限

1. **只覆盖单字**：水杉辅助码按字取码，词表（`dict/ciyu.txt`）不参与转换。
2. **补码不进方案**：解书靠 `.F` 区分同码的繁异/同义字，方案文件只收两位字母，`.F` 一律丢弃；同音同形码的字在水杉侧可能同码。繁体不靠补码输入，改用解书码打简体、由水杉繁体输出转繁即可。
3. **字母体系不同源**：解书主码字母取自解书部首表，水杉原生方案的字母另有取法，两者不能混用，也不存在换算关系。
4. **补位 `a` 必须显式写出**：主码唯一时解书只有一码，出口处补 `a` 凑两位。`a` 是解书的**占空码**——副码为空时的占位，解书码表里省略不写；水杉的辅助码本身可以只写一位，但它没有这套「副码 a」占位机制，少写一位就等于该字只有一码，故这里一律显式补上。
