RIME · 挂表即用

在 Rime 里·用上解书音形

跑一次导出脚本，两端都能用

想在 Rime 里用解书音形，先把一套方案文件放进用户资料夹。方案标识 jieshu， 菜单名「解书音形」。在仓库根跑一次导出，重新部署、勾选方案，Windows 小狼毫（Weasel） 和安卓同文（Trime）就能打字。码表还是 dict/ 里那份，脚本不改它； 你装过的其他方案也不受影响。

Before You Start

先确认三件事。

部署用的是仓库自带的导出脚本，标准库就够，不用另外装东西。

01 / RIME

已装 librime 发行版

Windows 用 小狼毫 Weasel，安卓用 同文 Trime v3.3.x。还得知道 RIME 用户资料夹在哪：小狼毫在托盘菜单「用户资料夹」，同文在 App 菜单 → 配置 → 用户文件夹。

02 / PYTHON

本机有 Python 3

导出脚本 rime_export.py 只依赖标准库，不用 pip 安装任何东西。

03 / REPO

仓库是完整的

脚本从仓库根 config.py 读取码表路径，真源在 dict/。 克隆仓库 后，命令都在仓库根执行。

想先看看手感，手机端 Web 演示在浏览器里就能打开，输入流程和候选逻辑都能试， 不用装任何东西。顺手了再回来挂表。

Deploy

导出、部署、启用。

三步打完就能出字。两端跑的是同一份方案和查询逻辑，文件落点不同： Windows 直接写进用户资料夹，安卓先导出到预备文件夹，再整份拷进手机。

STEP 01

在仓库根导出

Windows 小狼毫直接跑第一条；安卓同文用第二条，先导出到一个预备文件夹。

Windows · 小狼毫
python migrate_to_rime\rime_export.py
Android · 同文（先导出到预备文件夹）
python migrate_to_rime\rime_export.py --target <预备文件夹>
第一次运行会问 RIME 用户资料夹的绝对路径，答完写进仓库根 config.py 的 RIME_USER_DIR，以后不再问。留空就放弃，一个文件也不写。 换了资料夹记得同步改这一行，不然还往旧路径写。
STEP 02

让 Rime 读进去

Windows 在托盘菜单选「重新部署」。安卓把预备文件夹里的内容全部复制到手机 RIME 用户文件夹，再到 App 内「重新部署」。

STEP 03

切换到「解书音形」

Windows 在托盘「输入法设定」里勾选「解书音形」，确定后会自动再部署；安卓在方案选单里切换到「解书音形」。

打 bu44 出「不」、ba13 出「八」，能看到字就装好了。

0.6.7 正式发布时打算把导出产物打包进 GitHub Release， 到时候解压到 RIME 用户资料夹就能用，脚本也不用跑。

Platforms

选你的那一端。

两端的编码、门控、逐字选择、自动上字、优先上词都按同一套逻辑跑，共用一份 jieshu.schema.yaml 和 5 个 Lua 模块。皮肤与键盘各一份， 导出时一起给，各端只认自己那份。

WINDOWS

小狼毫 Weasel

  • 在仓库根跑 python migrate_to_rime\rime_export.py，脚本会把文件写进你的用户资料夹。
  • 托盘菜单选「重新部署」。
  • 「输入法设定」里勾选「解书音形」，确定后自动再部署。
  • weasel.custom.yaml 管皮肤，宣纸双配色和字体布局都在里面。
  • 「输入法设定」会回写已部署的皮肤文件，下次导出按本目录的真源覆盖回去。

ANDROID

同文 Trime

  • 导出时加 --target <预备文件夹>，脚本会自己建目录。
  • 把预备文件夹里的内容全部复制到手机 RIME 用户文件夹。
  • App 内「重新部署」，再到方案选单切换到「解书音形」。
  • 键盘是方案 H（10 列 × 5 行），键盘 ID 和方案 ID 同名，切换方案就自动绑定。
  • 候选栏每行候选数设成 5。找不到这一项，先把「横向候选样式」调成 AUTO_FILL。

与手机端 Web 原型相比，同文上暂不做翻译与部件表浮层，候选排列与翻页由同文系统接管； 差异逐项对照与键盘机制说明见完整技术文档 · 第三节。

What Gets Installed

只会新增这些文件。

文件名都以 jieshu / weasel / trime 开头，落在你的 RIME 用户资料夹里， 其他方案和用户词库不动。脚本按校验 → 渲染 → 逐字节同步 → diff 摘要 → 原子写走一遍，另留一份 *.bak 备份。

文件作用端
jieshu.schema.yaml方案定义，含自动上字 / 优先上词两个开关两端共用
jieshu.dict.yaml方案声明的词典；Trime 部署校验必需两端部署
weasel.custom.yaml小狼毫皮肤：宣纸双配色 + 字体布局Windows
trime.custom.yaml同文键盘：方案 H 布局 + 3 个 preset_keysAndroid
lua/jieshu_*.lua5 个模块：查询、原生候选垫片、门控、逐字定位、自动上字两端共用
lua/data/jieshu_single.txt单字真源逐字节拷贝，查询层运行期直读两端共用
lua/data/jieshu_ciyu.txt词表真源逐字节拷贝两端共用
jieshu.dict.yaml 别删。同文重新部署会校验方案声明的词典，缺了直接失败； 小狼毫不读它，导出也照样生成。两端皮肤和键盘互不认，整份拷进去不会打架。

First Keys

装好了，然后呢？

先照着余码提示打几个字。候选后面那串是还差的编码，补全就唯一命中。 碰上同音同主码的字，再回头翻副码规则也来得及。

SINGLE

单字

bu44 → 不；ba13 → 八；ba13. → 捌（补码点号）。

CHAIN

连续编码

bu44ba13 →「不八」链；yig →「一个」。系统自动拆分长编码。

PHRASE

词语与分段

ceu →「测试」；用 ' 手动分段，b;du'ceu →「病毒测试」。

Go Deeper

要改配置，先看真源。

这一页只讲怎么装。实现概要、功能表、组件顺序和维护要点、同文键盘差异、回滚办法， 都写在 migrate_to_rime/README.md 里。要改方案、皮肤或键位，先读那份。

MAINTENANCE

日常维护

码表更新后，在 main.py 整理真源，再重跑一次导出并「重新部署」，一次刷新词典、Lua 数据与方案配置。

CAUTION

改配置前必看

组件顺序有硬约束；engine/filters 不要加 uniquifier；开关默认开要写 reset: 1。 七条都在 2.3 节。

ROLLBACK

回滚

删掉用户资料夹下 jieshu*、build/jieshu*、lua/jieshu_* 与对应皮肤文件， 取消勾选方案再重新部署。仓库和 dict/ 不用动。

migrate_to_rime/README.md

导出脚本、Lua 模块、方案配置、两端皮肤和键盘，连部署与维护的细节都写在这里。这一页只管装到能打字，细节就不重复了。
