## 二、副码与补码规则设计

### 术语约定

以下术语贯穿全章，统一使用：

| 术语       | 含义                          | 别称（不推荐）  |
| -------- | --------------------------- | -------- |
| **前四码**  | 编码的前四位（ABCD），决定一个字在码表中的基本位置 | —        |
| **同四码字** | 前四码完全相同的若干字                 | 前四码同字    |
| **前四码组** | 一组同四码字的集合                   | —        |
| **空副码字** | 副码为空的字（最常用字）                | 四码字、无副码字 |
| **含副码字** | 副码非空的字                      | 有副码字、五码字 |
| **含补码字** | 含补码的整字                      | 含点字      |
| **点前编码** | 通过点"."代替余字余音显示的简写           | 正字码      |
| **正字**   | 与同四码组里其他字区分开的"标准"字          | 简体字（不完全） |

### 副码存在性原则;副码推导必须先查重

**副码是为了区分重码才存在**,不是每个字都必须有。**核心教训**:副码的存在前提是前四码冲突。看到余字能推导出副码来源,不等同于应该给副码。

**正确流程**:

1. 先确定ABCD(前四码)
2. 查前四码是否有重码
3. 只有重码才需要副码来区分,无重码则副码省略
4. 余部与余音是优先级关系(非互斥):当判断为优先取余部时,如果没有余部或不可拆分或被更常用字占据,则取余音。当判断为优先取余音时,如果没有余音或被更常用字占据,则取余部。

**常见错误**:把「能推导出副码」和「需要副码」混为一谈。前者是技术步骤,后者是冲突判定。

### 音托 / 别码与副码路径的关系：

当余字是表内部首时,其部首码**无论音托还是别码,都参与副码判断**。区别在于进入的路径不同：

- **别码部首**：部首码 ≠ 初码 → 走「部首别码」路径,无需音似性判断,直接排在空副码之后的第一优先级。为什么必须提前拦截？因为别码部首的部首码不等同于余音,若按余字解析码默认流程,会走到错误方向。

- **音托部首**：部首码 = 初码 → 部首码与余音是同一个字母,走「余字解析码」路径,需做音似性判断。音异则取余音（此时余音 = 部首码,两条路径收敛到同一字母）;音似则取余部。

实例：「耗 hk4nm」——余字「毛」是表内部首,初码 m = 部首码 m（音托）。「毛」máo ≠「耗」hào → 音异 → 取余音 m。这里取 m 既是取余音,也是取音托部首码,两者等价。

**副码优先级全景（含术语标注）**：

```
空副码
  ↓
部首别码（别码部首的部首码,不等同余音,无需音似性判断）
  ↓
余字解析码
  ├─ 音异取余音（此时若余字是音托部首,余音 = 部首码,自然带入）
  └─ 音似/难读取余部
  ↓
e → ; → 其余字母 
```

### 余字解析码的正确决策结构

**入口判断(无部首别码时)**:

```
   音似性判断
     ├─ 音异且易读 → 余音(终点)
     └─ 音似/难读(不成字=难读) → 取余部 → 余部综合规则
           ├─ 1. 余部首传递
           ├─ 2. 一般余集合选取
           ├─ 3. 结构特殊规则
           └─ 4. 单笔画规则
```

**关键纠正**:一般余集合选取不是音似判断前的独立入口。「不成字视为难读」→ 自然落入取余部路径 → 在余部综合规则中由一般余集合选取处理。

**余部综合规则的「综合」含义**:四条子规则不是互斥的线性 if-else,而是可交叉验证的策略集合。复杂字(如羲)可以多条路径都试,择优取用。

### 音似的本质是声旁判断

**核心洞见**:音似/音异的根本目的是判断余字是否为声旁。

- 声旁发音与整字相近 → 区分度低 → 跳过余音,取余部获得更高区分度
- 多音字基于文白异读 → 任一常用读音初码与整字相同即音似(如"行"háng初码h = "珩"初码h → 音似)
- 规则将"是不是声旁"这个直觉判断客观化为"初码是否相同"

**多音字余字判定规则**:余字的**任意一个**常用读音初码与整字相同 → 音似

### 音似判断中的「常用读音」筛选

**对「音似的本质」一条的重要细化**。

**原规则**:余字的任意一个读音初码与整字相同 → 音似

**细化后规则**:余字的任意一个**常用读音**初码与整字相同 → 音似。异体字读音、通假字读音**不参与判断**。

**原因**:音似的本质是判断余字是否为声旁。异体字/通假字的读音是其他字符的读音,与该余字本身的声旁关系无关。比如「齐」读 jì 时是「跻」的异体字,不是「齐」本身的常用读音--这个 jì 不能证明「齐」与「济」音似。

**判断步骤**:

1. 列出余字的所有读音
2. 剔除异体字读音和通假字读音,只保留**常用读音**
3. 用常用读音集判断音似:任一常用读音初码 = 整字初码 → 音似;否则 → 音异

**实例对照**:

| 字       | 整字初码 | 余字  | 剔除的读音(原因)         | 保留的常用读音   | 匹配? | 判定         |
| ------- | ---- | --- | ----------------- | --------- | --- | ---------- |
| 济 ji4uq | j    | 齐   | jì(跻异体)、jī(剂异体)   | qí        | q≠j | **音异**→取余音 |
| 摭 vi2uu | v    | 庶   | zhù(煮异体)、zhē(遮异体) | shù       | u≠v | **音异**→取余音 |
| 珩 hg2w  | h    | 行   | 无                 | xíng、háng | h=h | **音似**→取余部 |

**注意**:「行」的 xíng 和 háng 都是「行」字本身的常用读音,没有一个是为其他字借用的,因此两个都要看。这与「齐」「庶」的情况有本质区别--后者的 ji1/ji4/vu4/ve1 分别属于「跻」「剂」「煮」「遮」,不是余字本身的读音。

### 多音余字音异时的余音选取逻辑

**前提**:余字已判定为音异(余字不是声旁),且需决定余音/余部的选择。规则推荐优先取余音,但多音余字有多个读音可选。

**这不是强制规则,而是推荐优先级。**

**三层决策逻辑**:

**第一层 - 常用度碾压**

余字有一个读音的常用度远超其他读音时,直接取该读音的初码。

例:「是」有 ui4 和 ti2 两个读音。ui4 的常用度远高于 ti2 → 取余音 **u**

**第二层 - 语感直觉**

两个(或多个)读音都很常用,难分高下时,凭构词频度、语体语境等直觉选择更容易联想到的那个读音。

例:「长」有 ih2(cháng)和 vh3(zhǎng)。ih2 构词范围更广(长度、长短),vh3 偏口语化和方言化 → 取余音 **i**

**第三层 - 均不常用 → 视为难读 → 转取余部**

所有读音都不常用,无法凭直觉区分时,判此余字为「难读」,放弃余音路径,转而取余部。此时进入余部首传递等余部逻辑。

例:「咅」可能的读音 fu2/pb3/bi4/tb4 都不常用,无法直觉判定 → 判为难读 → 取余部,部首传递「口」→ 副码 **k**

**设计意图**:余音应该取「最容易想到的读音」,因为副码服务于用户记忆--它应该是自然联想,而非需要查证冷僻读音才能确定的编码。

### 难读与音似同属取余部路径

**"音似或难读 → 取余部" 是一条统一路径**,不是两条。难读不是特殊规则,它和音似触发同一个分支。

**箍 gu1zu 实例分析**:

- 箍 = 竹(z) + 㧜(i. 结构)
- 余字㧜难读 → 落入「音似或难读 → 取余部」路径
- 㧜分解为 扌 + 匝 → 取扌 → 扌↦手
- **u 是「手」的部首码**(手在部首表中,部首码 u)
- 㧜不在部首表中,没有部首码;但它的部件「手」有部首码
- 区分:u 是「手」的部首码,不是「㧜」的部首码

### 余部首传递的捷径:参照余字编码

**核心发现**:在余部首传递路径中(音似/难读 → 取余部 → 余部首传递),绝大多数情况下**副码 = 余字的主码**。

**原理**:

- 主码选取:整字主码 = 整字部首(在表内)的部首码
- 余部首传递:副码来源 = 余字部首(在表内)的部首码
- 两者是同一操作在不同层级上的镜像

**验证实例**:

| 字   | 编码    | 余字      | 余字主码 | 副码  |
| --- | ----- | ------- | ---- | --- |
| 瘆   | uf4bs | 参 cf1s  | s    | s   |
| 迸   | bg4zd | 并 b;4d  | d    | d   |
| 伦   | lp2rr | 仑 lp2r  | r    | r   |
| 拭   | ui4ug | 式 ui4g  | g    | g   |
| 痹   | bi4bt | 畀 bi4tq | t    | t   |

**两层过滤**(副码 ≠ 余字主码的情况):

1. **表外部首处理**:余字部首不在表内(简并、代替等) → 副码取初码而非部首码（注：如果是变体统一，仍取部首码）
   - 锌 xn1jl:余字辛→主码 d(立→亠简并),但副码 l(立初码)
2. **结构特殊规则**:阻止抛外取内,取上/左部件 → 绕过整字主码
   - 意 yi4xl:余字音→主码 r(日),但取上部立→l

**四层前置限制**(副码=余字主码的适用条件):

1. 整字需要副码,且该副码未被更常用字占用 → 副码存在性前提
2. 余字是音似(或难读)合体字、在码表中、不能太生僻 → 确实走到余部首传递路径，且得有主码可以查
3. 余字无部首别码,或别码已被更常用字占用 → 否则别码优先级更高,不进入余字解析码
4. 余字部首在表内 + 无特殊结构 → 两道过滤网不触发

### 同四码同余字同需副码：常用度驱动余部首传递优先权

**场景**：同一前四码组内，多个字的前四码相同、余字相同、都需要副码。此时所有字的副码首选都是同一个字母（根据余部首传递得到），但只有一个字能拿到它。

**规则**：常用度排序决定谁优先走余部首传递（拿余字主码），次常用的字递归下探余字的余部，取其他部件。

**典型案例——摞 vs 漯（lo4u 组）**：

| 字   | 部首     | 余字  | 常用度 | 副码首个候选                 | 结果    |
| --- | ------ | --- | --- | ---------------------- | ----- |
| 摞   | 扌→手(u) | 累   | 更常用 | 累主码 s（糸）               | **s** |
| 漯   | 氵→水(u) | 累   | 次常用 | 累主码 s → 被占 → 递归累的余部「田」 | **t** |

摞和漯的部首不同（手 vs 水），但在部首表中共行（u 行），且读音相同（luò），导致前四码同为 lo4u。余字又都是「累」——都音似 → 都走余部首传递 → 累主码 s 是共同首选。摞更常用，优先拿到 s；漯的 s 被占，递归进入累的余部「田」→ t。

**多音字变体——漯的两个读音**：

漯的另一个读音 tà（ta4ul）更进一步验证了这套逻辑。当读 tà 时，整字初码 t ≠ 余字「累」初码 l → **音异** → 取余音 l。音异直接跳过了余部首传递，与摞不产生冲突。

| 读音  | 整字初码 | 音似性    | 副码路径      | 副码  |
| --- | ---- | ------ | --------- | --- |
| luò | l    | l=l→音似 | 余部，递归 → t | t   |
| tà  | t    | l≠t→音异 | 余音 l      | l   |

同一个余字「累」，两个读音导致两种音似性判断，分别走进两条路径——这是多音字副码分叉的实证。

**与余部首传递捷径的关系**：捷径说「副码 = 余字的主码」，前置条件是四层全部满足，其中第一层就是「副码未被更常用字占用」。摞满足全部条件，直接走捷径——副码 s = 累主码 s。漯的 s 被摞抢占，第一层条件不满足 → 捷径不可用 → 退回完整路径（余部综合规则 → 余部首传递 → 递归拆累 → 取余部「田」→ t）。捷径是查表省步骤，完整路径是逐层递归；捷径走不通时，完整路径接手，两者输出可能不同。

**优化分配案例--「进」引用繁体余字**:

进 = 辶(z) + 井。井是音似独体(j=j),不可拆,只能余音=j,但 j 区分度不够。
→ 参考繁体「進」的余字「隹」。隹 ∈ 部首表(隹部),有部首别码 w。
→ 进 zw,副码 w 来自隹的别码,而非井的初码。

### 变体统一 vs 非部首字代替：副码递归中的身份判定

**核心问题**：副码选取中，余部递归遇到某个表外部件时，它能不能取部首码（进而走部首别码）？这取决于它跟部首表中某个部首的**关系性质**——是「同一个部首的不同写法」，还是「两个不同的字」。

**变体统一**：廾就是卄，龶就是青，巜就是巛——它们是同一个部首的古今/隶变异体。字形不同，**身份相同**。

- 卄在部首表中有部首码 c → 廾**继承**部首码 c → 有部首别码
- 巛在部首表中有部首码 x → 巜**继承**部首码 x → 有部首别码
- 在副码递归中，遇到变体部件 → 直接走部首别码通道 → **递归终止**

**非部首字代替**：夫不是矢。它俩是两个不同的字，只是因为夫不在部首表里，规则用矢来近似它。

- 矢在部首表中 → 矢有部首码 u
- 但夫≠矢 → 夫的部首码**不能**是 u → **无部首别码**
- 在副码递归中，遇到夫的部件 → 走余字解析码（余音 f，且"夫"不能继续拆）

**判定依据（查规则 3.4 节两表）**：

- 部件出现在「**变体统一**」表中（亅→丨、廾→卄、巜→巛 等）→ 有部首码，可传递
- 部件出现在「**非部首字代替**」表中（夫→矢、玉→王、曰→日 等）→ 无部首码，不可传递

**实战意义**：「这个部件算不算部首」不是玄学问题，去变体统一表和非部首字代替表里查一下就有答案。在变体表里 = 算，在代替表里 = 不算。

### 副码候选的多条件收敛判定法

**来源**:「巉 ij2ut」的副码推导中四种候选方案(t/d/b/;)的对比分析。

**核心思想**:当同一副码有多个候选时,不应单纯依赖「直觉优先」或「规则优先」,而是从多个独立维度交叉验证,看哪条候选获得的独立支撑最多。

**四条评分维度**:

1. **字义维度**:余字的字义是否指向某个部件?(如毚=狡兔→兔 t 得分)
2. **字形维度**:拆开后子部件的字义是否与上一级余字同源?(如㲋亦似兔→t 再得分)
3. **码表习惯维度**:该部件(或其关键部件)在码表中已有的编码是什么?(如兔 tu4d→⺈是部首来源→t/d 路径在兔的编码中合一→t 得分)
4. **记忆成本维度**:用户在看到这个字时,最可能自然联想到哪个部件?有没有需要额外知识才能触发联想的路径?(如比/匕需要康熙部首知识→b 扣分;未简标记→; 扣分)

**各维度权重**:

| 维度   | 权重    | 理由                       |
| ---- | ----- | ------------------------ |
| 字义   | ★★★   | 用户最自然的知识来源--会读/会认字的人知道字义 |
| 字形   | ★★★   | 用户直接看到的--拆字是视觉操作         |
| 码表习惯 | ★★    | 已掌握规则的用户已有的编码直觉          |
| 记忆成本 | ★(反向) | 需要额外知识的路径是记忆负担,需扣分       |

**对巉的完整评分**:

| 方案  | 编码    | 字义(兔)    | 字形(㲋亦兔) | 码表(兔主码d=⺈) | 记忆(-成本)         | 总计    |
| --- | ----- | -------- | ------- | ---------- | --------------- | ----- |
| t   | ij2ut | ✓        | ✓       | ✓(t/d合一)   | 直接可见            | 3/4   |
| b   | ij2ub | ✗        | ✗       | ✗          | 需康熙部首+简并        | 0/4   |
| d   | ij2ud | 间接(兔主码d) | ✗       | 间接(兔部首)    | 需变体知识           | 0.5/4 |
| ;   | ij2u; | ✗        | ✗       | ✗          | 需简化字知识+整字标记用于部件 | 0/4   |

**此框架的通用性**:不仅适用于巉,任何副码候选多的冷僻字都可以用这套多条件交叉验证来判定最优方案。规则服务于此判定而非支配此判定--多条件收敛到的结论如果和规则路径不一致,以多条件为准。

**原则**:不是「选了t因为直觉优先」,也不是「选了b因为规则优先」,而是「t 在三条独立维度上都获得支撑,b 只有一条--这不是偏向t,这是收束」。

### 「同义不同形」单音异体字的补码选取方案

**适用前提**（与「冷僻读音可主动放弃」互为镜像）：

- **该字是单音字**（不是多音字）——所以不能走"放弃收录"路线（参见 `memory/05_单字分析与案例教训.md` 中两阶段判定口诀）
- **该字是异体字**（与某个正体字同义不同形）——正体字在码表中已有编码

当异体字的本字（正体）已存在于码表中，**且该异体字本身极不常用**（如仅见于人名/古文僻用），异体字走补码路线，而非按自身字形独立取码。下面以「坖」为例，完整展示决策过程。

#### 案例：坖（ji4x.t）

**背景**：「坖」是「忌」的异体字，仅见于人名（如明穆宗朱载坖），极不常用。「坖」是单音字（读 jì，无其他读音）。

**字形分析**：上下结构，元 + 土。按自身字形，部首为土（t），独立编码应为 `ji4t`。

**字义分析**：坖 = 忌，二字同义不同形。「忌」在码表中已编码为 `ji4x`（心部）。

**两条路径对比**：

| 路径   | 编码       | 部首来源     | 优劣                   |
| ---- | -------- | -------- | -------------------- |
| 字形路径 | `ji4t`   | 土（按自身结构） | 符合直觉优先，但与「忌」毫无关联     |
| 补码路径 | `ji4x.t` | 心（继承正体字） | 编码关联清晰，不消耗新的 ABCD 槽位 |

**决策原则**：

1. **冷僻度优先**：极不常用异体字不值得独占前四码。空出 `ji4t` 留给更常用的土部字。

2. **溯源关联**：补码后缀 `.t` （这里是**副码逻辑选出来的部首码**——因为坖无地区性、走类比为新余字的路线——与 `.t = 台湾异体` 是不同的机制层，仅是字母重合） 与基码 `ji4x` 共同指向正体字「忌」。用户查「忌」时就能顺藤摸到「坖」。

3. **补码后缀的选取**：坖的 `.t` **不是新造规则**，而是 `references/rules.md` 第 571 行「若某字对应多个常用繁体，其补码的选取规则与副码相同（即类比为新的『余字』进行区分）」的字面应用。副码机制本身继承自主码机制——主码逻辑（取部首）→ 副码逻辑（取余部/余音/查重）→ 补码逻辑（类比为新的余字）。

4. **补码后缀选取的两套机制并存**（地区码 + 部首码/副码逻辑）：核心原则：「**若能识别为地区，则用地区码；若除了地区外还有别的差异，则使用类似副码逻辑**」。两套机制严格分工：
   
   **【A 地区码】**：适用于**单一地区差异**的异体字，rules.md 第 570 行明文列举：
   
   | 后缀  | 含义     | 适用场景                  |
   | --- | ------ | --------------------- |
   | .f  | 大陆繁体   | 仅在大陆使用的繁体字            |
   | .g  | 港澳异体   | 港澳地区特有的字形             |
   | .t  | 台湾异体   | 台湾地区特有的字形             |
   | .j  | 日本汉字   | 仅在日本使用的汉字形            |
   | .k  | 韩国用字   | 仅在韩国使用的汉字形            |
   | .u  | 通假/古音字 | 古汉语通假字、记录古音的异体（功能性标记） |
   
   这些字母与部首码表**恰好有重合**（f/g/t/j/u/k 都是合法部首码字母），但**这里它们是地区码，不是部首码**。误读为「后缀就是部首码」是完全错误的。例：`気 qi47.j` = 氣的日本写法（`気`），`.j` 是日本汉字标记，不是「气」的任何部首码。
   
   **【B 部首码/副码逻辑】**：适用于**多差异**或**无地区归属**的异体字，rules.md 第 571 行明文规定「若某字对应多个常用繁体，其补码的选取规则与副码相同（即类比为新的『余字』进行区分）」：
   
   - **多个常用繁体**：復複 都是「复」的合法繁体（大陆繁体中都可用，仅在不同义项下选用），二者**非地区差异**——按「类比为新余字」走副码逻辑 → 后缀取各繁体自身部首的部首码：復 fu4u.t = 彳部 t、複 fu4u.y = 衣部 y（与地区码「台湾繁体 .t」「港澳异体 .g」等含义完全不同，这里恰好是「被选用的副码字母」与「地区码字母」重合）。
   - **无地区性异体**：坖 ji4x.t = 土部 t（无地区性，走副码逻辑）；榦 gj45.m = 木部 m（同理）。
   
   **【决策流程】**：
   
   ```
   异体字 X（正体字 Y）
   ├── X 仅在某地区独有？ ─ 是 → 取地区码 .f/.g/.t/.j/.k
   └── 否（多差异或无地区性）→ 按副码逻辑取 X 自身部首的部首码
   ```
   
   **字形层面的本质判定**（不依赖「异体字数量」，直接从字形判断地区码还是部首码）：
   
   1. **差异性质**：字形差异的核心是**讹变**（同一字在流传中写成不同形状，无字源差别）→ 地区码；差异有**字源基础**（不同词、不同义项、不同部首）→ 部首码/副码逻辑。衆（⿱血乑）与 眾（⿱罒㐺）字源上是同一个字（《说文》从乑从目，本义「多」），上部血/横目、下部乑/㐺 皆为讹变 → 取地区码；復/複 的差异落在义项与部首上，有字源基础 → 取部首码。
   2. **差异权重**：**地区特征差异 > 本体字形表意差异** 时，地区码更能反映本质。衆/眾 之间唯一稳定的分野就是地区规范，两形不承载任何表意或功能分工 → 标地区而非标部首。
   
   **后缀含义是可叠加的**：同一基码下可能有「地区码补码」和「部首码补码」共存，查重避免冲突即可。

5. **单音字前提**：坖是单音字，必须录入该音（不能放弃）。但录入方式可以选补码而非独立前四码——这是"录入方式"的优化，不是"录入与否"的妥协。

**通用方法论**——「同义不同形」异体字补码选取流程：

1. 确定正体字（即码表中已存在的常用对应字）
2. 异体字基码 = 正体字的 ABCD(E)（继承全部前四/五码）
3. 后缀按以下顺序判断：**(a)** 异体字仅是某地区独有 → 取地区码 `.f/.g/.t/.j/.k` 或 `.u`（通假古音）；**(b)** 否则（多差异或无地区性）→ 按主码逻辑取异体字自身部首的部首码（複 .y = 衣部 y、復 .t = 彳部 t、坖 .t = 土部 t、榦 .m = 木部 m）；**(c)** 仅一个常见繁体且与正体字区分足够 → 可仅用 `.` 不带字母（如寶 bk3b. = 宝 bk3b 的第一繁体）。
4. 查重确认 `.` 后缀无冲突（同一基码下多个补码字的部首码不能冲突——若冲突按副码优先级次选）

**与常规「按字形取部首」规则的关系**：补码路线是常规规则的**例外层**。常规规则以字形为准，补码以字义关联为准。补码前缀 `.` 显式标记了「这是例外」，前端因此能在候选列表中清晰区分正体与异体。

### 补码选取规则的另一层应用：`.+部首码` 标明「该字同时也是某行部首」

`rules.md` 第 571 行明文「其补码的选取规则与副码相同」过于宽泛，需在记忆文档中记录下这一具体应用：

**适用场景**：整字是**部首字**（既是独立汉字，又是某行部首）时，用 `.+部首码` 补码标明这一身份特征。

**选取逻辑**：后缀 = 该部首在部首码表中的部首码字母（从 `references/rules.md` 第 170-194 行的部首码表查出）。

**例子**（已验证实际码表）：

| 字   | 编码     | 部首  | 部首码 | 是否正字         | 说明                            |
| --- | ------ | --- | --- | ------------ | ----------------------------- |
| 宀   | mm22.b | 宀   | b   | 无正字（mm23 空）  | 本身是部首字、补码标 b 行宀部              |
| 亠   | tb23.d | 亠   | d   | 无正字（tb23 等空） | 同上，d 行亠部                      |
| 廾   | gs34.c | 卄   | c   | 无正字          | 廾→卄变体统一（rules.md 254 行），c 行卄部 |
| 凵   | kj3t.c | 凵   | c   | 有正字坎 kj3t    | 在正字「坎」基础上追加补码 .c，标明凵也是部首      |
| 阝   | fu4s.b | 阝   | b   | 有正字阜 fu4s    | 同上，b 行阝部                      |

**与「表内取部首码」的关系**（关键点）：「`.+部首码`」并不是另造规则——副码的核心方法（表内取部首码，见 rules.md）也会得出同样的字符。两者产出相同，仅是因为视角不同而被表述为两种说法：

- **部首码视角**：从部首码表中查「该字同时是哪个部首」→ 得 `b/d/c`
- **副码视角**：「取余字部首码」——把该字视为「作为某部首」→ 同样得 `b/d/c`

**不是「延伸」也不是「创新」**——只是「与副码相同」的另一种场景实例化，与復複「同正体字多繁体」、坖「无地区性异体」是同一规则的不同应用场景。

**【补码后缀选取的完整三场景】**（修订）：

1. **场景 A（地区码）**：异体字仅是某地区独有 → `.f/.g/.t/.j/.k/.u`
2. **场景 B（副码逻辑部首码）**：异体字多差异或无地区性 → 异体字自身部首的部首码（復複、坖、榦）
3. **场景 C（部首字标注部首码）**：整字本身是部首字 → 自身作为部首的部首码（宀、亠、廾、凵、阝）

补充：场景 B 和场景 C 都产出于「与副码相同」的同一规则，只是输入条件不同——场景 B 强调异体字差异，场景 C 强调身份标注。
